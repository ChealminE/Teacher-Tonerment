# 🫧 탄산수 속 CO₂ 용해도 AI 시뮬레이터

고등학교 화학 수업용 웹 시뮬레이터입니다. 학생이 한국어 문장으로 명령하면 탄산수의 온도·압력·뚜껑 상태가 바뀌고,
3D 분자 모형·기포·그래프로 **기체의 용해도**가 어떻게 달라지는지 바로 볼 수 있습니다.

> **탐구 질문** — 차가운 탄산수와 미지근한 탄산수, 뚜껑을 연 직후와 마신 직후, 탄산(CO₂)은 어디로 가는가?

## 핵심 개념

- 기체의 용해도는 **온도가 높을수록 감소**합니다.
- 기체의 용해도는 그 기체의 **부분압력에 비례**합니다(헨리 법칙).
- 녹아 있는 양이 평형 용해도보다 많으면 **과포화** 상태이고, 이때 **기포**가 생깁니다.

## 화면 구성

- **3D 뷰**: 유리병, 물, 헤드스페이스, 뚜껑, O=C=O 볼-앤-스틱 CO₂ 분자, H–O–H(104.5°) 물 분자, 기포.
  마우스 드래그(회전)·휠(확대), 터치 드래그·핀치 확대를 지원합니다. `카메라 초기화`, `확대 보기(수면 클로즈업)`, `물 분자 보기` 버튼이 있습니다.
- **상태 카드**: 온도, 병 속 CO₂ 압력, 주변 기압, 뚜껑, 용존 CO₂, 평형 용해도, 상태 배지(과포화·포화 평형·불포화)와 숫자를 대입한 계산식.
- **그래프 3종**: 용해도 곡선(현재 점이 곡선 쪽으로 움직임), 최근 60초 시간 그래프, CO₂·O₂·N₂ 기체 비교.
- **수동 조작**: 온도·병 속 CO₂ 압력·주변 기압 슬라이더, 뚜껑·흔들기·마시기 버튼.
- **실험 기록**: 표, CSV 저장(엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 포함), 표 복사.
- **AI 명령 입력창**(하단 고정): 예시 칩, 🎤 음성 입력(지원 브라우저만), 현재 해석 모드 배지.

## 사용법 — 예시 명령

입력창에 쓰고 Enter를 누르거나, 예시 칩을 누르세요. 쉼표·`그리고`·`~고`로 이어진 명령은 순서대로 실행됩니다.

| 명령 | 일어나는 일 |
|---|---|
| `온도 10도 올려줘` | 온도 +10℃ → 용해도 감소 → 과포화 → 기포 |
| `온도 30도로 맞춰줘` / `300K로 해줘` / `50℉로` | 온도 설정(단위 자동 변환) |
| `온도 열 도 내려줘` | 한글 수사도 읽음 → 온도 −10℃ |
| `압력 5000hPa로 해줘` / `2기압으로 맞춰` / `압력 100kPa 올려` | 뚜껑이 닫혀 있으면 병 속 CO₂ 압력, 열려 있으면 주변 기압 |
| `주변 기압 10hPa 올려줘` | 항상 주변 기압 변경 |
| `뚜껑 열어줘` / `뚜껑 닫아줘` | 유효 CO₂ 압력 3500 hPa → 0.41 hPa |
| `병 흔들어줘` / `5초 흔들어` | 3초(또는 지정 시간) 동안 기포 방출 속도 ×6 |
| `마셔줘` | 뚜껑 열고 2초 동안 37℃로 → 입 안에서 방출될 CO₂ 양과 탄산감 게이지 |
| `뚜껑 닫고 압력 5000hPa로 해줘` | 복합 명령: 닫기 → 가압 → 불포화 → CO₂가 녹아 들어감 |
| `지금 상태 기록해줘` | 실험 기록 표에 한 줄 추가 |
| `속도 20배` / `빠르게` / `멈춰` / `다시 시작` / `처음으로` | 시간 조절·초기화 |
| `수온이 오르면 물고기에게 어떤 일이?` | 질문하면 설명만 해 줌 |

정도 표현: **조금** = 5℃ 또는 100 hPa, **많이** = 20℃ 또는 500 hPa, 표현이 없으면 10℃ 또는 200 hPa. `2배`, `절반`도 이해합니다.
값의 범위(온도 0~80℃, 병 속 CO₂ 압력 0~6000 hPa, 주변 기압 300~2000 hPa)를 넘으면 잘라 내고 경고를 보여 줍니다.

## AI 모드 설정법 (선택)

기본은 **🧩 내장 해석기**(규칙 기반)이며, 키가 없어도·오프라인이어도 항상 동작합니다.
대형 언어 모델로 더 자유로운 문장을 해석하려면:

1. 상단의 **⚙ AI 설정**을 누릅니다.
2. **AI 모드 사용**을 체크하고 제공자를 고릅니다.
   - Anthropic Claude (기본 모델 `claude-sonnet-4-6`)
   - OpenAI (기본 모델 `gpt-4o-mini`)
   - Google Gemini (기본 모델 `gemini-2.5-flash`)
   - OpenAI 호환 사용자 지정 URL (예: `http://localhost:11434/v1` — Ollama, LM Studio 등)
3. 모델명을 확인·수정하고 **API 키**를 입력한 뒤 **저장**합니다. 입력창 옆 배지가 `🤖 AI 모드(모델명)`으로 바뀝니다.

- API 키는 **이 탭의 메모리 변수에만** 보관됩니다. 브라우저 저장공간·화면·콘솔에 남기지 않고, 새로 고치면 사라집니다.
- LLM 응답이 JSON 형식이 아니거나 검증에 실패하거나, 네트워크 오류가 나거나, **8초 안에 오지 않으면** 자동으로 내장 해석기가 처리합니다.
- Anthropic은 키가 비어 있으면 키 헤더 없이 한 번 시도합니다(claude.ai 아티팩트 미리보기에서 키 없이 쓰기 위한 동작). claude.ai에서 열면 AI 모드가 자동으로 켜집니다.
- 학생 기기에서 키를 쓸 때는 사용량 한도를 걸어 둔 키를 쓰세요. 이 저장소에는 어떤 키도 들어 있지 않습니다.

## 과학 모델 (src/core.js)

- 헨리 상수: `k_H(T) = k_H298 × exp(C × (1/T − 1/298.15))` (T: K)
  - CO₂ 0.034 mol/(L·atm), 2400 K · O₂ 0.0013, 1500 K · N₂ 0.00061, 1300 K
- 평형 용해도(g/L) = `k_H(T) × P_CO₂(atm) × 44.01`
- 유효 CO₂ 압력: 뚜껑 닫힘 → 병 속 CO₂ 압력, 뚜껑 열림 → 주변 기압 × 0.0004
- 시간 변화
  - 과포화: `dC/dt = −k_out(C − C_eq)`, `k_out = 0.02 × (1 + (T−5)/25)` /s, 흔들기 중 ×6, 감소분의 80 %는 기포·20 %는 수면 확산
  - 불포화: `dC/dt = +0.008 × (C_eq − C)` /s
- 온도·압력 변경은 1.5초에 걸쳐 부드럽게 바뀝니다(마시기는 2초).
- 초기 상태: 5℃, 병 속 CO₂ 3500 hPa, 주변 기압 1013.25 hPa, 뚜껑 닫힘, 용존 CO₂ = 평형값(9.22 g/L).

## 빌드·테스트

Node.js 18 이상이 필요합니다.

```bash
npm install      # three@0.128.0 설치 (빌드할 때만 필요)
npm run build    # src/ → docs/index.html 한 파일로 인라인
npm test         # node --test tests/ (과학 모델·해석기·빌드 결과물 검사)
```

- `src/index.html`: 화면 템플릿(`<!-- INLINE:CSS -->` 등 자리표시)
- `src/style.css`: 스타일(라이트·다크 테마)
- `src/core.js`: 과학 모델과 내장 자연어 해석기(DOM·THREE·fetch를 쓰지 않는 순수 로직)
- `src/app.js`: UI, Three.js 3D 장면, Canvas 그래프, LLM 호출, 채팅 기록
- `scripts/build.mjs`: 위 파일과 `three.min.js`(라이선스 주석 보존)를 `docs/index.html`에 인라인
- `tests/core.test.mjs`: 자동 테스트

`docs/index.html`은 외부 요청 없이 파일만 더블클릭해서 열어도 동작합니다(LLM 호출만 예외).

## 알려진 한계(단순화 가정)

- 뚜껑이 닫힌 병은 **외부에서 압력을 조절하는 가압 용기**로 단순화했습니다. 실제 병에서는 CO₂가 빠져나오면 헤드스페이스 압력이 올라가지만, 이 모델에서는 병 속 CO₂ 압력을 사용자가 정한 값으로 유지합니다.
- 뚜껑을 열면 병 속 CO₂ 압력도 대기 수준(주변 기압 × 0.0004)으로 떨어지며, 다시 닫아도 자동으로 가압되지 않습니다.
- 헨리 상수의 온도 의존은 단순 지수식이며, 염·당 같은 용질 효과, CO₂의 탄산 이온화(H₂CO₃/HCO₃⁻), 물의 증기압은 무시합니다.
- 기포 방출은 1차 속도식 하나로 표현했습니다. 핵 생성·기포 크기·표면적의 영향은 3D 장면의 연출일 뿐 계산에 쓰이지 않습니다.
- "마시기"는 병 전체가 입 안 조건(37℃, 뚜껑 열림)이 된다고 가정한 사고 실험입니다.
- 3D 분자 수는 용존량에 비례한 **표현용 숫자**이며 실제 분자 수가 아닙니다. 분자 크기도 실제보다 매우 크게 그렸습니다.
- 내장 해석기는 정규식·키워드 사전 기반이라 복잡한 문장(조건문, 부정문 등)은 잘못 이해할 수 있습니다. 이때는 예시처럼 짧게 말하거나 AI 모드를 쓰세요.
- 음성 입력은 Web Speech API를 지원하는 브라우저(Chrome, Edge 등)에서만 보입니다.

# 🐟 수온과 용존산소: 물고기 생존 AI 시뮬레이터 (`/fish/`)

같은 저장소에 들어 있는 두 번째 시뮬레이터입니다. 탄산수 앱과 코드를 공유하지 않는 **독립된 앱**이며(`fish/` 폴더), 빌드 결과물은 `docs/fish/index.html` 한 파일입니다.

> **탐구 질문** — 여름철 폭염에 양식장 물고기가 집단 폐사하는 이유는 무엇일까? 수온, 산소, 물고기 수, 에어펌프는 어떻게 연결될까?

- 배포 주소: `https://<사용자명>.github.io/<저장소명>/fish/` (탄산수 앱과 같은 GitHub Pages 설정을 그대로 씁니다)
- 상단의 **← 탄산수 시뮬레이터** 링크로 두 앱을 오갈 수 있어요.

## 핵심 개념

- 기체의 용해도는 **온도가 높을수록 감소**합니다.
- 기체의 용해도는 그 기체의 **부분압력에 비례**합니다(헨리 법칙). 그래서 고지대에서는 용존산소 포화량이 줄어듭니다.
- 수온이 오르면 포화량은 줄고 물고기의 산소 소비는 늘어납니다(**이중 타격**).

## 화면 구성

- **3D 뷰**: 유리 수조, 반투명 물, 수면 위 공기층, 모래·자갈·수초, 에어스톤·호스·펌프. O=O 볼-앤-스틱 O₂(빨강), N≡N N₂(파랑, 공기층에 O₂ : N₂ ≈ 1 : 4), 희미한 H–O–H 물 분자(토글).
  - 녹아 있는 O₂ 분자 수 = round(DO / 15 × 120), 최대 120개. 수온이 높을수록 분자가 빠르게 움직입니다.
  - 과포화(DO > C_sat)면 물속 O₂가 수면 위로 빠져나가고, 불포화면 공기층 O₂가 수면으로 녹아 들어옵니다. 에어펌프를 켜면 에어스톤에서 기포가 올라가며 기포 주변에서 O₂가 퍼집니다. 물고기 근처의 O₂는 아가미 쪽으로 빨려 들어가 사라집니다(호흡).
  - 물고기: 정상(유영) / 호흡 가쁨(아가미가 빠름) / 수면 호흡(수면에서 입을 뻐끔) / 폐사(회색, 멈춘 채 수면으로 떠오름). 송어는 은색·분홍 줄무늬, 잉어는 금갈색. **물고기를 클릭·탭하면 상태 말풍선**이 떠요.
  - 드래그 회전, 휠·핀치 확대, `카메라 초기화`, `수면 클로즈업`, `N₂ 보기`, `물 분자 보기`. 30fps 아래면 분자 수를 자동으로 줄이고, 탭이 숨겨지면 멈춥니다. WebGL이 없으면 안내문이 뜨고 나머지 기능은 그대로 동작합니다.
- **상태 카드**: 수온, 기압(해발고도), 에어펌프, 어종, 물고기 수(생존/전체), 생존률, 포화 DO, 실제 DO, 어종 기준 배지(쾌적·주의·위험·치사), 헨리 법칙 해석 식.
- **시나리오**: 폭염(1℃/분씩 32℃까지), 고산 호수(해발 2000 m), 과밀 양식(50마리), 에어펌프 비상 가동.
- **그래프 3종**: 용해도 곡선(어종 DO 기준 색 띠, 쾌적 수온 띠, 치사 수온 선, 산소 결핍량 화살표), 최근 120분 시간 그래프(포화 DO·실제 DO·생존률), CO₂·O₂·N₂ 기체 비교와 연결 질문.
- **실험 기록**: 시뮬레이션 시간(분)·수온·기압·고도·에어펌프·어종·생존/전체·포화 DO·실제 DO·생존률·상태. CSV(UTF-8 BOM) 저장, 표 복사.
- **AI 명령 입력창**: 탄산수 앱과 같은 구조(내장 해석기 + 선택적 LLM, 8초 타임아웃 후 자동 폴백, 0.3초 간격 순차 실행, 🎤 음성 입력).

## 예시 명령

| 명령 | 일어나는 일 |
|---|---|
| `수온 5도 올려줘` / `물 온도 조금 식혀줘` | 수온 +5℃ / −2℃ |
| `주변 기압 10hPa 내려줘` | 기압 1013.25 → 1003.25 hPa, 포화 DO 약 1 % 감소 |
| `해발 2000m 호수로 옮겨줘` / `고도 500m 올려` | 해발고도 → 기압으로 환산 |
| `에어펌프 켜줘` / `폭기 꺼줘` | k_a 0.05 ↔ 0.30 /분 |
| `물고기 30마리 더 넣어줘` / `물고기 다섯 마리 빼` | 마릿수 변경(폐사한 물고기는 건져 내고 다시 기준을 잡음) |
| `잉어로 바꿔줘` / `무지개송어로 바꿔줘` | 어종 변경(같은 수를 새로 입식) |
| `폭염 시작해줘` / `고산 호수로 옮겨줘` / `과밀 양식` / `에어펌프 비상 가동` | 시나리오 |
| `에어펌프 켜고 물고기 열 마리 빼줘` | 복합 명령: [pumpOn, changeFishCount −10] |
| `지금 상태 기록해줘` / `속도 60배` / `멈춰` / `처음으로` | 기록·시간 조절·초기화 |
| `탄산수는 왜 차갑게 보관할까?` | 질문하면 설명만 해 줌 |

정도 표현: **조금** = 2℃ · 10 hPa · 5마리, **많이** = 10℃ · 100 hPa · 20마리, 표현이 없으면 5℃ · 50 hPa · 10마리.
값의 범위(수온 0~40℃, 기압 500~1100 hPa, 고도 0~5000 m, 물고기 0~60마리)를 넘으면 잘라 내고 경고를 보여 줍니다.

## 과학 모델 (fish/src/core.js)

- 포화 DO(1 atm, Benson–Krause): `ln C*₁ = −139.34411 + 1.575701×10⁵/T − 6.642308×10⁷/T² + 1.243800×10¹⁰/T³ − 8.621949×10¹¹/T⁴` (T: K)
- 기압 보정: `C_sat = C*₁ × (P − P_wv)/(1 − P_wv)`, `P_wv(hPa) = 6.112 × exp(17.62·t/(243.12 + t))`
- 고도 ↔ 기압: `P(hPa) = 1013.25 × (1 − 2.25577×10⁻⁵·h)^5.25588` (기압을 바꾸면 고도를 역산해 표시)
- 실제 DO: `dDO/dt = k_a(C_sat − DO) − n_alive × r(T)`, `k_a` = 0.05(펌프 끔)/0.30(켬) /분, `r(T) = 0.004 × 2^((T−20)/10)` mg/L/분
- 위험률 `h = h_DO + h_T`(/분), 생존 비율 `dS/dt = −h·S`, 살아 있는 수 = round(S × 기준 마릿수)
- 시간 단위는 시뮬레이션 분(×1 = 실제 1초당 1분, ×10, ×60). 수온·기압 변경은 실제 1.5초 동안 부드럽게 바뀝니다.
- 초기 상태: 20℃, 1013.25 hPa(해발 0 m), 에어펌프 끔, 무지개송어 20마리(100 L), DO = 정상상태 값 7.49 mg/L

| 어종 | 쾌적 수온 | 상한 치사 수온 | DO 쾌적 | DO 주의 | DO 위험 | DO 치사 |
|---|---|---|---|---|---|---|
| 무지개송어(냉수성) | 10~**20**℃ | 25℃ | ≥7 | 5~7 | 3~5 | <3 |
| 잉어(온수성) | 20~28℃ | 35℃ | ≥5 | 3~5 | 2~3 | <2 |

### 명세 기본값에서 바꾼 값과 이유

- **무지개송어 쾌적 수온 상한 17℃ → 20℃**: 상태 배지는 DO 등급과 수온 등급 중 나쁜 쪽으로 정합니다. 상한이 17℃면 초기 상태(20℃)가 '주의'가 되어 "초기 상태에서 송어가 쾌적" 조건(테스트 3)과 맞지 않습니다. 무지개송어는 20℃ 안팎까지 큰 스트레스 없이 견디므로 20℃로 넓혔습니다. 위험률 h_T는 명세대로(22℃ 미만 0)이므로 생존 계산에는 영향이 없습니다.
- **산소 소비에 쓰는 마릿수**: 반올림한 정수 대신 연속값 `S × 기준 마릿수`를 씁니다(화면 표시는 반올림). 물고기가 한 마리씩 죽을 때 DO가 계단처럼 튀지 않게 하기 위해서입니다.
- **DO 하한 0**: 산소 소비가 공급보다 커서 DO가 음수가 되면 0으로 자릅니다(무산소 상태).
- 수온 등급: 쾌적 범위 밖(높거나 낮음)은 '주의', (치사 수온 − 3)℃ 이상은 '위험', 치사 수온 이상은 '치사'. 차가운 쪽은 h_T가 없고, 물고기 행동도 '정상'으로 둡니다.
- 나머지 수치(포화식, k_a, r(T), h_DO, h_T, 시나리오 값)는 명세 기본값 그대로입니다.

참고 결과(자동 테스트와 같은 조건, 120분): 송어 30℃ 생존률 약 9 % · 잉어 30℃ 약 98 % · 잉어 33℃ 50마리 펌프 끔 약 34 %(DO 3.7) vs 켬 약 89 %(DO 5.7).

## 알려진 한계(단순화 가정)

- 수조 전체의 DO가 한 값으로 고르게 섞여 있다고 가정합니다(깊이에 따른 차이, 수면 근처의 높은 DO는 3D 연출일 뿐 계산에 쓰지 않음).
- 담수만 다룹니다(염분 보정 없음). 광합성(수초), 세균 분해, 먹이에 의한 산소 소비는 없습니다.
- 물고기 호흡량은 크기·활동량과 무관하게 한 마리당 같은 값이며, 산소가 부족해도 호흡량이 줄지 않습니다(DO가 0이 되면 소비가 멈춘 것으로 처리).
- 생존률은 결정론적 평균값이며 개체별 차이가 없습니다. 3D에서 어떤 물고기가 폐사할지는 무작위로 고릅니다.
- 어종 기준표는 교육용 근사값입니다. 실제 양식 기준은 어종·크기·순응 상태에 따라 다릅니다.
- 3D 분자 수는 표현용 숫자이며 실제 분자 수가 아닙니다. 분자 크기도 실제보다 매우 크게 그렸습니다.
- 내장 해석기는 정규식·키워드 기반이라 복잡한 문장은 잘못 이해할 수 있습니다.
